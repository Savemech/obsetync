# ObsetyNC 1.13.0

## Sync on large vaults

- Tree v1 can verify which index chunks belong to a root without copying every file path. In a 25,000-file test, that check used 7 WASM allocations, down from 25,084, with the same verified root.

- Tree v1 reads index chunks directly from their existing buffers when preparing updates. Updating files under a wide directory now builds its list of child nodes across successive steps, allowing the client to yield between them.

- Uploads classify files by their full size. Files at or just above 4 GiB previously wrapped to a small size when the client chose between whole-file and chunked upload.

- When an entire pending batch exceeds the tree memory budget, the client can remember the refusal across retries while the work, sync settings, tree and budget are still current. This avoids repeatedly preparing a batch that cannot fit. Debug info shows the available tree budget and the refusal.
- During a pull, registering expected file-change events takes less CPU when many writes are awaiting verification. The client checks for local edits again before publishing a downloaded batch, so an edit made during a download can still be reconciled.
- The **Upload priority** setting names the operation it controls. **Newest first** orders local edits by modification time. A fresh download processes server diff pages in the order received.

## Concurrent edits and recovery

- Stopping a push now reaches pending index and content checks and ranged chunk/manifest uploads. On the legacy server path, a local bookkeeping failure after the journal acknowledgement no longer puts already-sent changes back in the queue.

- An interrupted first write during large-file download setup can restart from its checkpoint. If cleanup cannot remove an obsolete checkpoint, it preserves the associated staged bytes for retry.

- On mobile, recovery after a compatibility transition now respects the pause after an interrupted sync. Select **Sync now** to resume.

- If one device deletes a folder and another edits a file inside it, Tree v1 now merges each path independently. An edited file can survive the merge while untouched siblings stay deleted.
- Text merges preserve line endings and whether the last line ended with a newline. Insertions in the middle of a document no longer consume the following base line.
- If local storage fills up immediately after enrollment, keep Obsidian open, free space and use **Sync Now**. The plugin retries saving the credentials it already claimed before starting sync. Closing Obsidian can lose credentials that exist only in memory.

## Self-hosted servers

- An unreadable saved root now surfaces as a server error. A request for an absent historical revision still returns 404. Legacy JSON diffs reuse the original file paths during serialization.

- The version explorer shows the files added in the first revision. Device names with punctuation render as text, and vault links preserve reserved URL characters.
- Historical exports verify each chunk as it is written to the temporary tar. Large chunked files no longer need to fit in memory as a single buffer.

- Explicit HTTPS URLs are respected. Upgrading an enrolled vault with legacy URL settings preserves the endpoint the client actually used. Select HTTPS explicitly to switch that connection.
- A temporary pack-file read failure keeps the object in the index so it can be read again when storage recovers.
- The Nix server image can initialize a fresh Docker volume as its standard unprivileged user. Existing bind-mounted data directories continue to use host filesystem permissions.

## Verification scope

The integration suites exercise interrupted publication, concurrent edits and recovery against an isolated server. Both packaged WASM variants passed the parity suite. Initial-sync throughput and peak memory on a physical iPad still require device measurements.
