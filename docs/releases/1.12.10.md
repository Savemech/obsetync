# ObsetyNC 1.12.10

## Changes

- Small-file downloads no longer wait for a complete durable journal append,
  echo verification, and acknowledgement after every individual write. Echo
  work now drains at the existing byte/file-bounded batch boundary, allowing
  the journal's existing transaction batching to work even with apply
  concurrency set to one.
- Every apply window still yields and checks cancellation. Download ownership
  stays charged until the batch's echo work and checkpoint settle. Existing
  memory budgets, local-edit checks, and serial large-file transfers remain.
- Debug exports include separate disk-write and pull-echo wait phases, plus
  accumulated phase times for active operations. This distinguishes local
  storage bookkeeping from network transfer time during a long download.

## Verification

The regression uses the real journal with 9,008 pending entries, 64 downloads
of 32 KiB each, native-call scheduling, and a same-size local edit during pull.
It reduces durable journal publications from 128 to 18 while writes remain
serial, preserves all pending edits through journal reload, and stays within
the configured 32 MiB transient workset budget. These are synthetic storage
measurements, not an iPad throughput or total process-memory benchmark.

Coverage also checks legacy and paged pulls, changing apply limits within a
batch, live progress, cancellation between writes, and final ownership release.

## Upgrade

Update through BRAT or install the release ZIP. No vault reset or store
migration is required. Existing queued changes are preserved for reconciliation.
The startup delay remains 30 seconds by default. Sync Priority still controls
upload order; download ordering is unchanged.
