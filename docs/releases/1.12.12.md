# ObsetyNC 1.12.12

## Fix

Tree v1 pushes could stop with `CandidateMutationOutputAdmissionDeniedError`
after many successful syncs. Native commit/abort already freed obsolete tree
nodes, but the plugin kept their historical output charges. The reported case
had a 6.16 MiB live tree and an 85 MiB resident charge under a 96 MiB policy
limit, leaving too little allowance for the next 64-file batch.

The atomic commit/abort receipt now covers Tree v1 as well as Tree v2. A valid
v1 receipt bounds the charge by all surviving node payloads and the complete
root allocation and tree identity strings. The host can only shrink the existing lease; an initially
unadmitted graph never grants extra allowance. Invalid receipts or changed
ownership retain conservative accounting. Both push and pull use this shared
settlement path.

Memory limits, publication checks and journal acknowledgements are unchanged.
This removes the accumulated accounting error without raising the memory cap
or acknowledging files that have not been published.

## Verification

- Native tests compare v1 commit/abort receipts with actual surviving chunks
  and root String/Vec capacities, including failed and repeated terminal calls.
- Host tests start with an 85 MiB historical charge, repeat commit/abort, and
  cover malformed receipts and partially admitted graphs. Both tree formats
  retain the strict receipt validation tests.
- The packaged-WASM regression runs 33 admitted candidate cycles with 64-file
  updates on a 25,000-file v1 tree and checks the ledger against live output
  after every cycle. Scalar/SIMD memory verification checks both v1 outcomes.

These checks cover the scoped tree-output ledger, not total process memory or
a guarantee against every device crash. Genuine capacity refusals remain.

## Upgrade

Update the plugin to 1.12.12 and reload it in Obsidian. Keep the existing vault,
settings and journal; no reset or re-enrollment is needed. A server upgrade or
Tree v2 migration is not required for this fix.
