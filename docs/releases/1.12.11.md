# ObsetyNC 1.12.11

## Changes

- Mobile pull-echo verification now admits one file source at a time. Previously
  many callback verifiers could retain source buffers while waiting for the
  shared Obsidian adapter queue, despite the displayed read concurrency of one.
  Journal transactions still batch, and every echo still requires verification
  before acknowledgement. Local edits remain protected.
- Parent folders are checked before creation. Saving another file into an
  existing folder no longer repeats the adapter's native mkdir and folder
  reconciliation. The check uses fresh metadata, so a deleted folder is recreated
  without relying on a stale directory cache.
- After an interrupted mobile sync, automatic startup remains paused until
  **Sync now** is selected. This includes interruption evidence saved by earlier
  versions. The acknowledgement survives reloads; the same historical record
  does not keep pausing subsequent startups. Caught errors and desktop startups
  retain their previous behavior.
- Debug output now distinguishes parent-folder preparation (`mkdir`) from the
  actual adapter write (`write`), and includes the Obsidian API version and
  startup interruption hold. Both IO timings include adapter queue waits.

## Verification and limits

The pull regression now serializes journal IO, file writes, and echo reads on
one shared adapter queue. With 9,008 existing pending changes and 64 downloads
of 32 KiB, it verifies that only one echo source is admitted, all original edits
and an interleaved same-size edit survive journal reload, and byte/callback
owners drain. The new source-bound assertion fails with the previous verifier.
Platform tests cover existing/deleted folders, concurrent folder creation,
native errors, exact binary slices, and phase closure. Startup tests cover the
hold across reloads, explicit resume, and acknowledgement persistence.

These are synthetic host tests, not an iPad throughput or process-memory
benchmark. The reported 1.12.10 run spent 4.9 minutes in its combined write path,
52.7 seconds waiting for echoes, and 2.8 seconds downloading. This patch removes
known local work and a source-buffer concurrency gap; the dump does not prove
the cause of the subsequent renderer crash or that all host-side delays are
resolved.

## Upgrade

Update through BRAT or install the release ZIP. Keep the existing vault and
journal; no reset or data migration is needed. If startup is held after the
previous interruption, select **ObsetyNC: Sync now** to resume deliberately.
Normal startup retains the default 30-second delay. Sync Priority still applies
to uploads; download ordering is unchanged.
