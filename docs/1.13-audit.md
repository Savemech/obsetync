# ObsetyNC 1.13 module audit

Status: in progress. Starting point: `c166ecac7bb216915b70e32e1c56915004c05f37`
(1.12.12). Work branch: `master`. Publish verified commits directly to master,
as requested by the user; PR review is not a workflow requirement.

## Requested outcome

Review every code module, trace its production callers and tests, fix concrete
discrepancies, remove obsolete or unreachable implementations, and ship a
verified 1.13.0 release through the repository's existing release and `just ship`
workflows. This includes the Rust workspace, Obsidian plugin and workers,
wire schemas, test/benchmark tooling, build/deployment configuration and the
documentation describing those contracts.

Expected load includes desktop and iOS vaults with tens of thousands of files,
interrupted syncs, concurrent devices, and a fleet still using Tree v1. Existing
wire formats, durable state and memory safety limits remain real compatibility
requirements. A compiler warning or an unreferenced exported symbol alone is
not enough evidence to remove an external or dynamically invoked API.

## Completion evidence required

1. Every tracked code/configuration file in `1.13-module-audit.tsv` has an
   explicit review disposition and evidence; generated files and fixtures are
   distinguished from production entry points. New or deleted files are
   reconciled with that inventory.
2. Confirmed findings are fixed with their callers, tests, fixtures and docs,
   or have a concrete documented reason to retain them. No unresolved defect
   introduced by the cleanup is accepted as completion.
3. Rust, TypeScript, native WASM, browser/worker, E2E and Nix/release gates cover
   the affected behavior. Tests of declarations alone do not prove runtime use.
4. Version declarations and release notes agree on 1.13.0; the committed build
   is deployed through `just ship`, tagged/pushed, published, and verified from
   the actual installed and downloaded artifacts.

## Coverage

The TSV is the exhaustive file inventory. `pending` means not reviewed, `read`
means inspected but callers or behavior still need checking, and `reviewed`
requires evidence. A passing repository test suite does not turn pending rows
into reviewed rows. Generated code is reviewed through its schema/generator and
consumer contracts. Historical benchmark measurements remain evidence, not
active production modules. `removed` records an intentionally deleted module
and the evidence that it had no production owner.

## Findings

### 1. Disconnected automatic-push timer

`plugin/src/sync.ts` constructs an Obsidian debounce callback, but all live
listeners trigger `MaxLatencyCoalescer` instead. The old field is only assigned
or cleared. Removed the abandoned callback, import, global test hooks and
Obsidian mock exports. The early-rejection regression now triggers the actual
automatic coalescer under strict unhandled-rejection handling. The coalescer's
existing ordering/lifetime tests and the full plugin suite pass. Status: fixed.

### 2. Live-document store has no production owner

`crates/sync-server/src/doc_store.rs` is declared by `main.rs`, but its store and
operations have no callers outside its own tests. The existing CRDT HTTP/WS
routes use `crdt.rs`, a separate active implementation. After tracing all
references and the durability ADR, removed the 1,616-line prototype and module
declaration. The ADR and roadmap now identify it as deferred design, with the
prototype retained in Git tag 1.12.12. Active CRDT compatibility routes remain.
The Rust workspace tests pass. Status: fixed.

### 3. Nix plugin package omits stylesheet

`flake.nix` installs `main.js`, `manifest.json` and both WASM variants, but omits
`plugin/styles.css`; Docker and GitHub releases include it. Added the existing
stylesheet and built `nix build .#plugin`. The actual output contains all seven
expected files, including CSS and both scalar/SIMD WASM pairs. Status: fixed.

### 4. Build and operational documentation describes retired paths

README build commands can extract an old cached image without `--build`, the
artifact diagram still shows a `wasm/` subdirectory, and several comments still
describe certificate/CA setup and named cache volumes. Updated the README and
build comments against Compose extraction, packed storage, segmented sync base,
startup failure handling and current root-head paths. Removed the obsolete CA
directory from new layouts and corrected the settings URL example to HTTP.
Nix reproducibility now names source identity and target platform as inputs;
the README no longer claims that init can recover erased data. Status: fixed.

### 5. Unused browser-worker ownership field and local symbols

The browser worker retained a field containing an already-transferred
qualification buffer; no code read it. Actual ownership accounting uses
`qualificationInFlightBytes` and transfer validation. Removed the unused field,
its assignments, an identical-arm conditional and three unused type/import
bindings. Enabled TypeScript `noUnusedLocals` and `noUnusedParameters`.
Type checking and the browser worker unit suite pass. Status: fixed.

### 6. Maintenance reset leaves recoverable content and races the live writer

`clean-server` deleted only roots and loose files while the server was still
running. Packs, legacy group journals and CRDT logs survived; legacy journal
recovery could make acknowledged objects visible again. The recipe also relied
on a shell absent from the Nix image. It now stops the server, invokes the native
offline `clear-vault-data` command, and restarts only after success. Cleanup
validates all target directories before deleting anything and preserves keys,
devices, replay windows, enrollment, metadata and caches. Tests cover unexpected
files, symlinks, missing initialization, repeat cleanup and preservation. An
isolated Nix-binary smoke test removed ten fixture files, preserved seven, and
started a healthy server; actual just recipe execution with a Docker recorder
proved stop/cleanup failure prevents later steps. No production data was used.
Status: fixed; direct CLI invocation requires the server to be stopped.

### 7. Development and release WASM toolchains drifted apart

The dev image downloaded only an unchecked x86 wasm-pack and installed distro
Binaryen, while production/CI duplicated pinned architecture checks and hashes.
All four Docker/CI callers now use `scripts/install-wasm-tools.sh`. It rejects
unsupported architectures and verifies both archives before installing either.
Tests cover x86/ARM aliases, native detection and both checksum failure paths.
The actual dev build also exposed `Unable to locate package just` in bookworm;
just now installs through the existing Cargo tool setup. A real dev image build
and tool execution passed (wasm-pack 0.13.1, Binaryen 117, Rust 1.95.0). Nix's dev
shell was missing wasm-pack; it now supplies the locked 0.13.1 package, verified
by executing it inside the shell. Status: fixed; native ARM execution pending.

### 8. Restored configuration can redirect the server to the old data directory

`run --data-dir /restored` loaded `/restored/config.json` but used the old
`data_dir` string inside it for all storage. Loading now binds storage to the
explicit command argument. Removed the unused port/password config fields and
the unused copy stored in AppState; listening ports continue to come from CLI options
with the same defaults. Older JSON remains readable and newly initialized JSON
retains the data_dir field needed by older servers and native test tooling.
Regression and native smoke tests restore an old config to a new path, remove
the original path, start a healthy server and verify writes use the restored
store with the same key. Status: fixed.

### 9. Managed WASM build rejects valid optimizer paths containing spaces

The version probe invoked an unquoted executable variable. Moving the existing
contract fixture into a directory with spaces reproduced a false version error
before wasm-pack ran. Quoting the executable fixes it; all optimizer-version
and installer tests now pass. Status: fixed.

### 10. Concurrent initialization can replace the server identity

`init_box_keypair` checked existence and then overwrote the final private-key
path. A synchronized 16-thread test reproduced different successful identities
for one data directory. A second test reproduced a missing public copy after
an interrupted initialization. The existing tempfile dependency now stages the
private key with Unix mode 0600, syncs it, and publishes without replacement;
all initializers load the winning key. The public copy is atomically repaired,
files and Unix directory ancestors are synced, and malformed existing private
keys remain errors without being overwritten. Both regressions pass, including
eight rounds of concurrent initialization. Status: fixed; non-Unix execution
and physical power-loss behavior were not tested.

### 11. An old WebSocket can replace or erase a reconnected device's presence

Presence was keyed only by device, so closing an old socket cleared a newer
socket's announcement. A matching session check alone still allowed delayed
old frames to reclaim presence; a deterministic test reproduced that case.
Presence now records a monotonically ordered session ID, rejects older updates
while the newer presence is live, and only lets the publishing session clear
it. Broadcasts occur under the state lock to preserve mutation order. Per-vault
forwarders now use Tokio JoinSet ownership, which aborts them even when sending
the initial snapshot returns early. The close regression failed against the
previous Nix binary. State and native realtime regressions cover both late old
messages and close, including a ping barrier proving the old message was handled.
Status: fixed.

### 12. Disabled wire-v1 code and test-only helpers remain in production modules

Removed 423 lines of permanently disabled HTTP wire-v1 middleware and old
crypto tests guarded by `cfg(any())`; Git history retains the migration context.
The compiled HTTP v2 and both realtime WebSocket protocols remain unchanged.
Removed the unused ServerError Unauthorized variant and blanket dead-code
suppression, and limited CRDT frame inspection and the writer's test convenience
entry point to test builds. Corrected crypto comments that still named removed
fields or overstated metadata privacy and nonce guarantees. Status: fixed.

### 13. Concurrent enrollment claims can return the same credentials twice

The record was read before registration and unlinked afterward, with removal
errors ignored. A paused-registration test reproduced two successful claims;
an injected removal failure also incorrectly returned credentials. Claims now
hold a stable filesystem lock through registration and consumption, check
removal errors, and sync the Unix directory before returning credentials.
Registration failures retain the code. A real child-process exit after durable
registration proves that the lock is released and a retry reuses one identity.
New records are published from complete 0600 Unix temporary files without
replacing a colliding code. The HTTP E2E test also gets exactly one successful
response from two simultaneous claims. Status: fixed; physical power loss
and non-Unix execution were not tested.

### 14. Ticket cleanup can delete another request's incomplete publication

A 16-thread mint/claim regression reproduced freshly minted tickets disappearing
because another mint's sweep read a partial final file and deleted it as corrupt.
Tickets now publish complete staged files without replacement; the sweeper only
examines completed tickets, claimed tickets, and explicitly named publication
temporaries. It leaves current writes alone and removes abandoned temporaries
after the existing TTL. Claims sync the Unix directory before allowing a
handshake, so consumed tickets cannot be accepted before that durability barrier.
Tests cover parallel publication, single-use claims, expiry, active and abandoned
temporaries, abandoned claims, matching v2 keys, and Unix 0600 file permissions.
Both realtime and data-lane E2E suites pass. Status: fixed.

### 15. One bulk-deletion approval can authorize concurrent pushes

The guard bypass used a read-then-unlink sequence. A synchronized test produced
five successful consumers of one approval; per-vault root locks do not serialize
one device across different vaults. Consumption now claims the marker by atomic
rename and syncs its directory before granting the bypass. Eight rounds of 16
concurrent consumers each produce exactly one winner. Existing root-outcome
tests continue to verify that capacity refusals retain an unspent approval.
Status: fixed.

### 16. Device metadata publication duplicates weaker platform-specific code

The bespoke writer created credential files with inherited permissions (0644
in the failing test), used a remove-before-rename Windows fallback, and synced
only the immediate parent even when registration created a new device directory.
It now reuses the existing tempfile dependency, writes Unix files as 0600 from
creation, syncs the file before replacement, and syncs directory ancestors.
The installed dependency's Windows implementation uses replacement flags;
Windows execution itself remains untested. Credential-directory traversal is
covered separately in finding 18. Status: fixed.

### 17. Device tests exercise retired filesystem registry implementations

Standalone list, last-seen and purge implementations survived only under
`cfg(test)`, alongside the production in-memory registry. Removed those copies
and the test-only method that bypassed authentication. List/purge tests now call
DeviceRegistry, and timestamp/coalescing checks drive its real authenticate and
flush path. Two redundant old-writer timestamp tests were removed; the live-path
test still covers both throttled and forced persistence. Status: fixed.

### 18. Legacy directory permissions expose credential filenames

Bearer tokens occur in token-index filenames, so 0600 file contents alone do
not protect credentials when other users can enumerate the directory. Unix
initialization and startup now create or repair `server/`, `server/ws-tickets/`,
`devices/`, `devices/tokens/` and `enrollments/` as 0700 before loading state or
opening listeners. All five paths are checked for files/symlinks before any
permission changes; offline cleanup performs this check before deleting vault
data. Existing keys, registrations and vault-directory modes are preserved.
Startup requires ownership of the credential directories; backup/restore docs
now describe this. Regression tests first reproduced inherited 0755 modes and
accepted symlinks. An isolated native restart verified all five modes, six
unchanged credential files, an existing device and a pending enrollment claim;
a child running as UID 65534 could enumerate the old directories but received
permission errors after restart. A symlinked credential directory failed before
listening or changing other directory modes. Status: fixed on Unix; Windows
directory permissions remain host ACL policy and were not exercised.

### 19. Explicit HTTPS settings are silently downgraded in three paths

The API constructor, settings reload and root-stream scope applied the old
HTTP migration repeatedly. Enrollment also replaced every numeric port with
27183 and discarded HTTPS. The API now retains the selected scheme, and both
WebSocket lanes derive ws/wss case-insensitively. An internal settings marker
performs a one-time migration for already-enrolled legacy settings, preserving
their actual HTTP endpoint and existing root-intent identity; later explicit
HTTPS choices survive reload. The stable HTTP scope digest remains unchanged.
Enrollment preserves proxy origins/prefixes, infers only the native HTTP
27182/27183 pair, and accepts an optional explicit admin URL for custom listeners.
Its URL and code are validated before dispatch. Actual native HTTPS proxy smoke
testing verified the certificate, path prefix, enrollment and a sealed authenticated
tree negotiation against a temporary Rust server. Status: fixed; actual Obsidian
and iPad TLS behavior remains part of the release gates.

### 20. Enrollment can overwrite credentials before rejecting the wire version

The admin JSON was trusted as an EnrollmentBundle and main copied the device ID,
token and pin before checking wire version. The API now validates the supported
wire, device identity, token, canonical 32-byte public keys and expiry before
returning a bundle. Main also rejects a result if either server address changed
during the request. Tests cover malformed responses and actual bundled-main
rejection without credential/settings publication. Status: fixed for these
response/address failure paths; broader settings publication/concurrency review
remains open below.

## Follow-ups from inspected modules

These are open audit work, not findings accepted as safe for the final release:

- The E2E enrollment code parser skips the
  last possible nine-byte window and can match a code-shaped device name instead
  of the dedicated code element.
- Review concurrent enrollment/reset/settings publication failure: the response
  and address rejection paths are now covered, but main's wider settings owner
  behavior still needs a complete audit.
- Legacy CRDT append does not fsync, WS relays even after append failure, and
  snapshot replacement can race updates. Full-log readback also lacks a bound
  before allocation. Its existing E2E test verifies live-server readback, not
  crash durability; the test name and comments now say so.
- Realtime notification connection/identifier/payload limits still need review
  alongside the process transport budget, which currently covers HTTP and WS
  data ownership. Plugin WS queue and connection-lifetime review is unfinished.
- The CLI health probe has read/write deadlines but no TCP connect deadline,
  and its status check only searches for ` 200 `. Review actual timeout/status
  behavior and listener error propagation before treating the CLI audit as done.
